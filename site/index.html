Executive Summary

Top 5 Macro Patterns Across 100 Apps

Insight over raw table: what the 100-app distribution reveals about building AI agent toolkits at scale.

Pattern #1 79% Bearer / 51% OAuth2

Bearer Tokens & OAuth 2.0 Eclipse Legacy Auth

Bearer tokens (Personal Access Tokens / Scoped Bot tokens) dominate the ecosystem (79 apps), with OAuth 2.0 (51 apps) preferred for multi-tenant customer apps. Static legacy API keys are in sharp decline—platforms like Airtable (Feb 2024 sunset) and HubSpot (Private Apps) have deprecated static keys in favor of scoped tokens.

Ops Action: Standardize on Bearer header injection & OAuth2 refresh loops.
Pattern #2 78% Self-Serve

78% of Apps Allow Instant Self-Serve Provisioning

78 out of 100 applications provide completely frictionless, automated paths to acquire API credentials (49 perpetual free tiers and 29 unrestricted free trials). Only 22% require paid plans (8%), partner/sales contracts (6%), admin review (5%), or lack public APIs (3%).

Ops Action: Automate 78% of toolkit generation via self-serve sandbox agents.
Pattern #3 Category Polarities

Dev & Productivity Lead; Finance & CRM Suffer Gating

100% of Developer/Infra tools and 100% of Productivity tools have self-serve API access. In contrast, Finance (40% gated) and Enterprise CRM (20% gated) suffer from severe commercial friction—merchant underwriting (Paygent Connect), institutional licenses (PitchBook, DealCloud), or KYC compliance.

Ops Action: Route FinTech & Enterprise CRM into dedicated Partner Ops pipeline.
Pattern #4 58% MCP White Space

Huge First-Mover White Space in Model Context Protocol

Only 6% of apps offer official MCP servers (GitHub, Slack, Cloudflare, Notion, Firecrawl, Devin). 36% have community servers. 58% of apps have ZERO MCP implementations, presenting Composio with an immediate opportunity to ship official toolkits for high-demand connectors like Plaid, Linear, Close, and Ramp.

Ops Action: Target 58 unbuilt MCP apps as high-priority Composio first-party toolkits.
Pattern #5 The 3 Architectural Traps

The 3 Hidden Blocker Archetypes: CLIs, Ghost APIs & Approval Walls

A standard research script often fails on edge cases. Our research identified three critical architectural traps:

1. The CLI Trojan Horses (Sherlock, Mermaid CLI): Popular developer repos that have NO hosted REST SaaS API. Must be packaged as local containerized CLI subshell tools rather than webhook connectors.
2. The Ghost APIs (fanbasis, Consensus, NotebookLM): Consumer apps with high user interest but zero public 3rd-party developer REST endpoints (NotebookLM requires Google Cloud Vertex AI).
3. High-Touch Approval Walls (Google Ads, LinkedIn Ads, Amazon SP-API): Public docs exist, but production credentials require rigorous developer vetting, MCC accounts, or AWS SigV4 signing.

Ops Action: Flag non-REST & high-touch apps early in human review queue to prevent pipeline stall.

🧑‍💻 Where a Human Was Needed (18 Apps Flagged)

The agent autonomously routed 18 uncertain or gated apps into human_review_queue.json. Humans stepped in across four distinct scenarios:

  • 1. Institutional Private Portals (DealCloud, PitchBook): Required human verification to confirm credentials cannot be self-served and require institutional enterprise client relationships.
  • 2. Closed Consumer Platforms (fanbasis, Consensus): Flagged when developer search yielded zero public API endpoints, preventing hallucinated OpenAPI specs.
  • 3. Commercial Underwriting & Waitlists (Paygent Connect, iPayX): Verified that merchant acquiring and private betas gate API access.
  • 4. Consumer App vs Cloud Developer API Disambiguation (NotebookLM): Human operator clarified that consumer NotebookLM has no API, and agent tools must instead wrap Google Cloud Vertex AI Gemini API.

Honest Post-Mortem

Where the Agent Failed & Nuanced Edge Cases

Full transparency on apps that challenged automated scraping and required specialized operational playbooks.

1

The "Ghost API" Trap

fanbasis, Consensus, NotebookLM

Customers frequently ask for toolkits for these popular applications. However, an automated agent searching for endpoints will either hallucinate or hit landing pages.

Finding: fanbasis has zero developer API. Consensus is in a closed pilot. NotebookLM has no standalone API (agents must wrap Vertex AI Search & Conversation).

2

The CLI Trojan Horses

Sherlock, Mermaid CLI

These tools are included in developer request lists alongside REST APIs, but have no network listener.

Finding: Sherlock is a Python command-line OSINT tool; Mermaid CLI compiles markdown diagrams via Puppeteer.

Composio Strategy: Build containerized CLI runners (exec toolkits) rather than HTTP REST integrations.

3

High-Friction Approval Review Gates

Google Ads, LinkedIn Ads, Amazon SP-API

These platforms have public documentation, leading standard agents to mistakenly declare them "100% buildable today."

Finding: In reality, generating a production token requires multi-week compliance reviews, manager MCC accounts, or AWS SigV4 cryptographic signing.
